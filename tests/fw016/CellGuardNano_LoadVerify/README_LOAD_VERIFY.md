# CellGuard Nano 0.1.6 — 부하 중 탭 역전 의심 검증 + 목표값 지정형 충·방전 시운전

**0.1.5를 설치한 기판에는 이번 0.1.6을 한 번 업로드해야 합니다.**
그다음 목표 전압 변경은 Pi 명령으로 합니다. 기존 정상용 펌웨어와
0.1.5 소스는 별도로 보존했습니다.

0.1.3/0.1.4로 실제 확인한 충전 회로를 바탕으로, 고정 시운전 단계와
`부팅당 충전 1회` 제한을 `RAMP`/`DRAIN` 명령 및 누적 에너지 제한으로
바꾼 0.1.5의 기능을 유지합니다. 0.1.6에서는 실제 방전시험에서 관찰한
`TAP_INVERSION`의 *부하 중 오측정 가능성*을 안전하게 구분하도록 했습니다.

**중요:** 이 버전은 부하 중 측정 경로의 근본 문제를 해결했다고 주장하지
않습니다. MOS ON 상태에서 역전 의심값이 나오면 즉시 전력을 차단하고,
그다음 무부하 전압을 검사합니다. 무부하가 정상이어도 **해당 단계를 실패로
종료하며 자동으로 충전·방전을 재개하지 않습니다.** 문제의 재현과
원인 분리를 위한 안전성 개선이지, 이상 측정값을 무시하는 패치가 아닙니다.

## 핵심 동작

| 항목 | 내용 |
|---|---|
| `RAMP,200` | 네 셀의 **저장 전압**을 기준으로 셀당 약 200 mV까지 충전 |
| `DRAIN,120` | 충전 뒤 셀당 약 120 mV까지 저항 방전(Q4, D10) |
| Pi 자동화 | 단계별 `RAMP` 실행 → 각 셀 전압 확인 → `DRAIN` → 유지전압 확인 |
| 업로드 횟수 | 이번 안전성 수정 후에는 목표값 변경 시 **추가 업로드 불필요** |
| 타이밍 | 충·방전 MOS ON 최대 120ms, 다음 ADC 측정 전에 OFF 최소 80ms |
| 검사 | ADC 기준전압, NTC, 4셀 전압, 탭 역전, 셀 불균형, 충·방전 반응 확인 |
| 통신 | CRC-16/CCITT-FALSE, 순서번호, Pi `PING` 하트비트 1초마다 |
| 부하 중 탭 역전 의심 | MOS 즉시 OFF → 80ms 이상 쉼 → 새 ADC 측정 → 실역전 TRIP / 정상 복귀 시 단계 중단 |

목표값은 **팩 전압이 아닌 셀 한 개의 전압(mV)**입니다. 4셀은
직렬입니다. 셀당 200mV라면 팩 약 800mV를 뜻합니다.

## 0.1.6 업로드하기

1. ZIP 전체를 풉니다. Arduino IDE에서
   `CellGuardNano_LoadVerify/CellGuardNano_LoadVerify.ino`를 엽니다.
2. 기존과 같은 Nano/ATmega328P 설정을 사용합니다. **외부 전원을
   끄고**, 지금까지 성공한 안전한 USB·기판 분리 방식으로 업로드합니다.
3. Nano를 다시 연결한 뒤 Pi의 `/dev/serial0`에서
   `$CGV,0.1.6-LOAD-VERIFY,...`가 나오는지 확인합니다.
4. `cellguard_cycle.py`를 Pi의 홈 디렉터리에 복사합니다. 별도 Python
   라이브러리 설치는 필요 없습니다.

업로드 직후에는 **출력을 동작시키지 않는 버전/셀 전압 확인**부터 실행하세요.

```bash
sudo python3 cellguard_cycle.py --probe-only
```

`PROBE: firmware=0.1.6-LOAD-VERIFY, ... relay=0, cells=[...]mV`를
확인합니다. 이 명령은 `SYNC`로 출력을 끄고 전압을 읽지만 `ARM`, `RAMP`,
`DRAIN`을 보내지 않습니다. `TRIPPED`가 표시되면 원인 확인 전 가동하지 마세요.

## Pi에서 실행 — 충전과 방전을 한 번에

처음에는 이전에 성공했던 낮은 목표에서만 재검증하는 것을 권합니다.

```bash
sudo python3 cellguard_cycle.py --charge-to 200 --discharge-to 120
```

방전 동작과 종료가 실제 로그로 검증된 다음에는, **다시 업로드하지 않고**
다음처럼 목표값만 변경할 수 있습니다.

```bash
sudo python3 cellguard_cycle.py --charge-to 400 --step 100 --discharge-to 200
```

이 명령은 현재 전압을 확인한 다음 200→300→400mV(현재 전압에 따라
앞 단계 생략)를 자동 실행하고, 각 단계마다 릴레이가 실제로 OFF된 뒤
전압이 유지되는지 확인합니다. 이후 Q4 방전 경로를 사용해 200mV로
내리고 다시 측정합니다. 정상이라면 `PASS`를 표시하고, 시간별 원본 UART
프레임은 `cellguard_cycle_YYYYMMDD_HHMMSS.log`에 저장됩니다.

2026-10-25 실기에서 200mV→120mV 및 300mV→200mV 방전은 성공했고,
400mV 충전 후 300mV 방전 시에는 부하 중
`tap=[352,696,612,955]mV`가 측정되어 `TAP_INVERSION` TRIP이 발생했습니다.
잠시 뒤 무부하 셀 전압은 `[318,319,310,335]mV`로 복귀했지만,
**부하 중 원인은 아직 미확정**입니다. 400mV 이상 재시험을 안전하다고
입증한 자료는 아닙니다. 기기 옆에서 전류·발열·셀 상태를 관찰하세요. 무응답,
과전압, 과온, 비정상 셀 간 편차 또는 중도 타임아웃이 발생하면 즉시
중단하며, 오류 이후 자동 재시도하거나 `RESET`하지 않습니다.

### MCU 명령 형식

다음은 CRC와 시퀀스를 제외한 *명령 내용*입니다. 수동으로 CRC를
계산할 필요 없이 Pi 스크립트가 자동으로 만듭니다.

```
CGC,<seq>,SYNC
CGC,<seq>,ARM
CGC,<seq>,RAMP,300
CGC,<seq>,PING
CGC,<seq>,OFF
CGC,<seq>,ARM
CGC,<seq>,DRAIN,150
CGC,<seq>,PING
```

충·방전 모두 정상 종료하면 강제로 **DISARM**되므로, 다음 단계에는
새로운 `ARM`이 필요합니다. `CHARGE,1` 또는 `DISCHARGE,1`처럼
목표값이 없는 무제한 ON 요청은 거부됩니다.

### 실험 제한 (펌웨어가 강제)

| 항목 | 제한 |
|---|---:|
| `RAMP` 목표 범위 | 셀당 150~1000mV |
| `DRAIN` 목표 범위 | 셀당 100~950mV |
| 충전 정지용 독립 상한 | 셀 1050mV, 팩 4200mV |
| 충전 중 강제 TRIP | 셀 1200mV, 팩 4600mV |
| 충전 중 부하 걸린 상태 별도 긴급 TRIP | 셀 1800mV, 팩 5200mV |
| 방전용 독립 하한 | 셀 25mV, 팩 80mV |
| 충·방전 차단 | 120ms ON / 최소 80ms OFF 뒤 ADC 측정 |
| 한 번의 `RAMP`/`DRAIN` 최대 시간 | 각각 25초/30초 |
| Nano 부팅당 MOS ON 누적시간 | 충전 60초 + 방전 60초 |
| 연속 활성 시 호스트 하트비트 | 5초 이내, Pi 스크립트는 1초마다 PING |
| 셀 간 편차 | 최대 80mV, 초과하면 latched TRIP |

정해진 목표에 먼저 도달한 셀 하나가 있으면 전체 팩을 정지합니다.
나머지 셀이 목표 전압에서 40mV 이상 벗어나면 Pi는 시험을 실패로
판정합니다. 셀 균형을 맞추기 위해 한 셀을 강제로 과충전하는 기능은
없습니다. 실제 `CELL_IMBALANCE`·`CHARGE_NO_RESPONSE`·
`DISCHARGE_NO_RESPONSE`·통신 장애가 있으면 정상적인 다음 단계로
넘어가지 않습니다.

### 부하 중 역전 의심의 새로운 진단 동작

1. MOS ON ADC에서 탭 역전을 발견하면 두 MOS 출력을 **즉시 OFF**합니다.
   온 상태에서 위험할 정도로 높은 전압/ADC 포화/AREF 이상은 기존처럼
   즉시 TRIP이 우선합니다.
2. 그 순간의 **부하 중** 원시 ADC 및 누적 탭 전압을 `$CGY` 프레임에
   기록합니다. 이 값은 저장된 셀 전압(`CGT`)으로 취급하지 않습니다.
3. 새로운 무부하 전압 샘플을 최소 80ms 휴지 후 받아 검사합니다.
   - 무부하에서도 역전 등 이상 지속: `TRIPPED`, MOS/릴레이 차단.
   - 무부하가 정상: `LOAD_TAP_VERIFY,...REST_OK` 기록 후
     `DRAIN_STOP` 또는 `CHARGE_STOP`의 이유를 `LOAD_TAP_UNSTABLE`로
     남기고 단계 중지/무장 해제/릴레이 OFF.
4. Pi는 `LOAD_TAP_UNSTABLE`을 성공으로 간주하지 않고 `ABORTED`를 표시하며
   별도로 `OFF`를 보냅니다. 같은 단계 자동 재실행은 없습니다.

여기서 `REST_OK`는 **무부하 셀 저장 전압이 정상이라는 뜻**이지,
실제 부하 연결 상태가 안전하다는 뜻이 아닙니다. 원인 확인 없이 상위
전압으로 진행하거나 보호를 해제해서는 안 됩니다.

`RAMP,1000`은 **허용 가능한 펌웨어 시운전 명령 상한일 뿐, 그 목표까지
실물의 안전성이 실증되었다는 뜻이 아닙니다.** 먼저 낮은 전압에서
충·방전 둘 다 검증하고 조금씩 올려야 합니다.

## 아직 해결하지 않은 하드웨어 한계

- **정격 2.7V/셀(합계 10.8V)까지의 완충은 이 펌웨어로 불가능합니다.**
  현재 약 5.26V 충전 레일만으로는 직렬 팩을 그 이상 충전할 수 없고,
  REF3040(4.096V) + 47k/43k 분압의 마지막 탭 ADC 범위도 약
  8.57V에 그칩니다. 이 영역에서 한계값을 소프트웨어로 올려도
  실제 충전 능력이나 전압 측정 범위가 확장되지는 않습니다.
- 현재 펌웨어는 MCU 내부 ADC와 소프트웨어 차단에 의존합니다.
  독립적인 과전압/과온 차단, 셀 밸런싱, 고전압용 측정 및 전원 구조가
  마련된 최종 운전판을 대체하지 않습니다.
- 정상용 `hardware_verification.h` 검증 플래그는 건드리지 않았고,
  ESR/누설/히터 명령은 계속 잠겨 있습니다.
- 0.1.5 충·방전은 300mV까지 실기 확인했으며, **0.1.6 새 보호 로직은
  아직 AVR 정식 컴파일 및 실물에서 확인하지 않았습니다.**

## 제작·검증 범위

- `validation/load_verify_smoke.cpp`의 가상 기기 시험에서
  **같은 Nano 부팅으로 RAMP 200→300→400, DRAIN 400→200**을 통과했습니다.
- 목표 없는 기존 명령 차단, 하트비트 5초 초과, 충전 경로 단선,
  방전 무응답, 셀 불균형, AREF 오류, 수동 OFF, MOS 펄스 시간 초과도
  확인했습니다.
- Raspberry Pi용 `cellguard_cycle.py`는 Python 표준 라이브러리만
  사용하며 CRC 검증, 순서번호, 단계별 2회 이상 정지전압 측정,
  하트비트 송신, 중단 시 `OFF` 전송, 로그 저장을 지원합니다.
- 부하 중 3번째 탭이 역전되는 실제 측정 사례를 주입한 모의시험에서
  **MOS부터 OFF → 80ms 무부하 확인 → 단계 중단**을 검증했습니다.
  무부하에서도 역전일 때 TRIP 유지, 정상시 자동재시작 금지, 실제 과전압
  즉시 TRIP도 별도로 검증했습니다.
- `validation/test_load_verify_pty.py`는 실제 Pi Python 스크립트를
  가상 UART와 연결해 정상 충·방전과 `LOAD_TAP_UNSTABLE` 실패 시 `OFF`
  전송을 각각 확인합니다.
